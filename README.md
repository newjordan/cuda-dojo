# CUDA Dojo

[![CI](https://github.com/newjordan/cuda-dojo/actions/workflows/ci.yml/badge.svg)](https://github.com/newjordan/cuda-dojo/actions/workflows/ci.yml)

CUDA Dojo is a public collaboration repo for a GPU-first chess engine and the measurement harness around it. The project is centered on single-GPU search, verification, and data collection. CPU orchestration is used for startup, UCI, and verification. CPU chess compute is not the target architecture.

The move generator itself is `__host__ __device__` code. A CPU machine can compile and test that generator. Search, the transposition table, and eval stay on the GPU.

## Quick start

These steps need Python 3.10+ and `g++`. They do not need CUDA.

```bash
python3 -m pip install -r requirements.txt
make test
```

`make test` builds the host perft and make/unmake binaries and runs pytest, which executes them. GitHub Actions runs the same checks on a CPU runner.

Useful pieces:

```bash
make -C cuda/engine host-test          # depth-4 perft and make/unmake symmetry
python3 -m pytest -q -rs               # perft counts, CPU tools, GPU skips
bash cuda/engine/run_tests.sh          # same host binaries; prints SKIP for GPU tests
```

GPU-only tests are marked `gpu` and are skipped when `nvcc` or a GPU is absent. `pytest -rs` prints the skip reason.

## Project structure

```text
cuda/engine/          Modular UCI engine. Move generation, make/unmake, attacks,
                      eval, transposition table, search, and UCI.
cuda/chess_mcts.cu    Standalone GPU MCTS experiment.
cuda/*.py, *.mjs      Audits, oracle comparison, corpus building, training helpers.
compression/          Board-fold and geometry encoders. Pure Python, no CUDA.
crawler_control/      Calibration-run control plane (seed manifests, dry-run probes).
gpu_spine/            Opening book and the Stockfish reference labeller.
trainers/             Lozza source and the Stockfish install target.
tools/                FrostMatrix render pipeline and vocab helpers.
schemas/              JSON schemas for calibration profiles and fighter IR.
tests/                pytest suite. Perft on standard positions, CPU tool checks,
                      and GPU tests that skip without CUDA.
.github/workflows/    CPU CI. Installs requirements.txt and runs the host tests.
```

Python dependencies for the CPU harness are pinned in `requirements.txt` (`chess` 1.11.2, which is python-chess, plus NumPy and pytest). Training dependencies are in `requirements-gpu.txt` (`torch` 2.15.0) and are not installed by CI. Node 18 or newer runs the `.mjs` tools. There are no npm packages to install.

## Running on a CUDA machine

Install the NVIDIA driver and a CUDA toolkit that provides `nvcc`. The Makefiles default to `/usr/local/cuda-13.0`. Point `NVCC` and `CUDA_PATH` at the toolkit you actually have:

```bash
export NVCC=${NVCC:-/usr/local/cuda/bin/nvcc}
export CUDA_PATH=${CUDA_PATH:-/usr/local/cuda}
```

Pick an architecture. The default, `dgx-spark`, is `sm_121` and will not load on other boards.

| `CUDA_SINGLE_GPU_TARGET` | Architecture |
| --- | --- |
| `dgx-spark` (default) | `sm_121` |
| `h200` | `sm_90a` |
| `native` | the GPU in this machine |

`native` is the right choice on a workstation or a cloud GPU that is not a DGX Spark.

```bash
export CUDA_SINGLE_GPU_TARGET=native

make -C cuda/engine engine
bash cuda/engine/uci_test.sh
make -C cuda/engine engine_test          # transposition table and Zobrist
make -C cuda chess_mcts

python3 -m pytest -q -m gpu              # the tests CI skipped
```

`engine_test` and `pytest -m gpu` compile with whatever `CUDA_SINGLE_GPU_TARGET` is set to, then run kernels. They need a visible GPU, not just the toolkit.

Stockfish is only used by the oracle labeller. It is not part of perft or the engine build:

```bash
bash ./install_stockfish.sh
# writes trainers/stockfish/stockfish_bin (Stockfish 18)
```

Some measurement scripts named in older notes (`gpu_fighter`, `nn_eval`, the family-persistence matrix) are not in this public tree. The commands above are the ones that build from this checkout.

## Tests

Perft uses the six standard positions from [chessprogramming.org](https://www.chessprogramming.org/Perft_Results): the initial position, Kiwipete, the endgame, the promotion mirror, and the two Steven Edwards positions.

- pytest walks those positions with python-chess and checks the published node counts at every depth whose tree is at most 500,000 nodes.
- `cuda/engine/engine_test_perft_host` runs the engine move generator at depth 4 on all six. The expected counts are 197,281; 4,085,603; 43,238; 422,333; 2,103,487; and 3,894,594.
- `tests/test_makeunmake_symmetry_host` checks that unmake restores the position byte for byte.

`tests/test_tt` and `tests/test_zobrist` launch CUDA kernels. `run_tests.sh` prints `SKIP` for them when CUDA is absent. pytest does the same for every test marked `gpu` (those two, the UCI smoke, and a short `chess_mcts` run).

## Current status

Recorded on the branch this public tree was exported from:

- `cuda/engine/uci_test.sh`: 11/11 passing on a CUDA machine.
- `cuda/engine/tests/test_perft.cu`: the depth-4 canonical perft passes. The host build above reproduces it without a GPU.
- `cuda/engine/tests/test_makeunmake_symmetry.cu`: passing.
- `cuda/engine/tests/test_tt.cu`: passing, including the torn-write race fix.
- False-finish regression gate: 5/6. King-pressure: 5/5. Queen-pressure: 4/8.
- Family persistence, where those scripts were run: at 1000 simulations, exact hits 9/14 and family top-3 hits 12/14. At 5000 simulations, exact hits 7/14 and family top-3 hits 10/14.

The GPU MCTS path is not stable across budgets yet. Queen-pressure and reverse-trap classes are still under-resolved. Scheduler and eval-service exist in `cuda/engine/` and are not yet the dominant runtime path.

Working rules: single GPU first, measured changes only, and verification gates decide whether an idea stays.
